# Hindi Style Guide

This style guide keeps translations consistent. Follow it in every pull request.

## Tone and register

- Use formal, respectful Hindi (the aap form) matching developer-documentation tone.
- Address the reader directly and politely.

## Terminology

- Always use the approved term from `glossary/glossary.csv` (mirrors the Notion glossary).
- Do not invent variants.
- Keep product names, CLI commands, code, URLs, and identifiers in English.

## Borrowed words and transliteration

- Use an established Hindi technical term where one exists (for example प्रमाणीकरण for authentication).
- Where the English term is standard for Hindi speakers, keep it in Devanagari (for example सर्वर for server) or in Latin script when clearer (API, HTTP).

## Formatting

- Preserve Markdown structure exactly: headings, lists, tables, and fenced code blocks.
- Keep inline code, commands, and URLs in backticks, untranslated.
- Do not translate text inside code blocks.

## Numbers and punctuation

- Use Arabic numerals (0-9), not Devanagari numerals, for technical values.
- Preserve punctuation and casing of code and identifiers.

## Gender and agreement

- Keep grammatical gender consistent for recurring nouns; when unsure, follow the glossary examples.
